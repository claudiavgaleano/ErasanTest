# SEO Implementation

Documentation of the SEO setup added to the Erasan React app, including meta tags, crawler configuration, and sitemap generation.

## Overview

This app is a client-side React SPA (Vite + React Router). SEO is handled in two layers:

1. **Static defaults** in `index.html` — available before JavaScript runs
2. **Dynamic per-route meta tags** via React components — updated on navigation

---

| File | Purpose |

| `src/config/seo.js` | Central SEO config (site URL, defaults, helpers) |

## Meta Tags (PageSeo)

`PageSeo` updates these tags on each route change:

- `<title>`
- `<html lang="...">` (based on active i18n language)
- `meta name="description"`
- `meta name="keywords"`
- `meta name="robots"` — `index, follow, max-image-preview:large, max-snippet:-1, max-video-preview:-1`
- `meta name="googlebot"` — same as robots
- `link rel="canonical"`
- **Open Graph:** `og:title`, `og:description`, `og:url`, `og:type`, `og:image`, `og:site_name`, `og:locale`
- **Twitter:** `twitter:card`, `twitter:title`, `twitter:description`, `twitter:image`

Pages can pass `noindex` to set `robots` and `googlebot` to `noindex, nofollow` (used for 404 states and the legal page).

## Crawler Configuration

### robots.txt

Located at `public/robots.txt`. Allows all user agents and explicitly allows Google crawlers:

- `Googlebot`
- `Googlebot-Image`

Points to the sitemap:

```
Sitemap: https://claudiavgaleano.github.io/ErasanTest/sitemap.xml
```

Update this URL when deploying to a custom domain.

### sitemap.xml

Generated by `scripts/generate-sitemap.mjs` and written to `public/sitemap.xml`.

Includes:

- Static pages (home, about, products, contact, etc.)
- All product pages from `src/data/products.js`
- All blog posts from `src/data/blogPosts.js`

Regenerated automatically on `npm run build`. To regenerate manually:

```bash
node scripts/generate-sitemap.mjs
```

## Configuration

### Environment variable

Set in `.env` (see `.env.example`):

```env
VITE_SITE_URL=https://claudiavgaleano.github.io
```

Used for:

- Canonical URLs
- Open Graph / Twitter image URLs
- Sitemap `<loc>` entries

When moving to production (e.g. `https://www.erasan.com`):

1. Set `VITE_SITE_URL` in `.env`
2. Update the sitemap URL in `public/robots.txt`
3. Rebuild: `npm run build`
4. Submit the new sitemap in [Google Search Console](https://search.google.com/search-console)

### Base path

The app is deployed under `/ErasanTest/` (see `vite.config.js` `base` and `package.json` `homepage`). Canonical URLs and sitemap entries include this path automatically via `import.meta.env.BASE_URL`.

## i18n

SEO titles and descriptions are translated under the `seo` key in:

- `src/i18n/locales/en.json`
- `src/i18n/locales/es.json`

`PageSeo` sets `og:locale` to `en_US` or `es_ES` based on the active language.

To edit copy for a page, update the matching `seo.<pageKey>.title` and `seo.<pageKey>.description` entries in both locale files.

---

## Adding SEO to a New Page

1. Add `seo.myPage.title` and `seo.myPage.description` to `en.json` and `es.json`
2. Add a route entry in `src/components/RouteSeo.jsx`:

```jsx
{ test: (path) => path === '/my-page', key: 'myPage' },
```

For dynamic pages, import and render `PageSeo` inside the page component:

```jsx
import PageSeo from '../components/PageSeo'

<PageSeo
  title="Page Title"
  description="Page description for search engines."
  path="/my-page"
  image="https://example.com/og-image.jpg"  // optional
  type="website"                             // optional: website | article | product
  noindex={false}                            // optional
/>
```

3. If the page should appear in the sitemap, add its path to `staticRoutes` in `scripts/generate-sitemap.mjs`

## Limitations (SPA)

Because this is a client-rendered SPA:

- Google can index JavaScript-rendered content, but indexing may be slower than with server-side rendering
- Social media crawlers and some bots may only see the default `index.html` meta tags unless they execute JavaScript
- For best social sharing previews and crawl reliability at scale, consider SSR, pre-rendering, or a meta-tag service for production
